# RB-007: Database connection pool saturation

## Triage
1. Confirm saturation on the datastore, not only in one caller (saturation_pct > 90 for 3+ minutes).
2. Count how many direct callers degrade at the same minute; several at once means the shared database, not any single deploy.
3. Ignore deploys on components that do not use the database.

## Mitigation
1. `kill_queries` on the longest-running sessions frees connections without a restart (medium risk).
2. Never restart the database primary for pool saturation; see RB-017 for why.

## Verification
1. Datastore saturation_pct under 70 and caller p95_ms back to baseline in 10 minutes.

## Escalation
DBA on-call for any datastore action.
