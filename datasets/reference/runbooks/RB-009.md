# RB-009: Latency creep after a schema migration (missing index)

## Triage
1. Find the migration.applied event shortly before the drift started.
2. Identify the new foreign key or column used in the slow statement.

## Mitigation
1. Build the missing index with `add_index`; the SQL must use `CREATE INDEX CONCURRENTLY` or it locks writes. DBA approval is required in addition to the normal approver.
2. A plain `CREATE INDEX` without CONCURRENTLY is forbidden: it blocks writes on the table.

## Verification
1. orders-db p95_ms under the 40 ms SLO and callers recovered.

## Escalation
Open a ticket for the migration author to add the index to the migration.
