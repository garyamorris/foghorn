# RB-001: Bad deploy: elevated errors right after a release

## Triage
1. Compare the deploy finish time with the first error_rate increase; the gap should be under 5 minutes.
2. Check that the changed component is on the call path of the failing endpoint (get_topology).
3. Look for a new exception signature in the changed component's logs that did not exist before the deploy.

## Mitigation
1. Roll back the last deploy of the changed component with `rollback_deploy` (medium risk, one approver).
2. Do not roll back unrelated components: a rollback elsewhere changes nothing and adds risk.

## Verification
1. error_rate and p95_ms of the changed component return to baseline within 10 minutes.

## Escalation
Page the owning team's on-call if the rollback does not restore the baseline.
